# 그릴박스 · 메뉴별 영양성분 페이지 (프로토타입)

정적 페이지(HTML/CSS/JS). 메뉴·영양 데이터는 `data/*.json`으로 분리, 코드 하드코딩 없음.
색·폰트는 `styles.css`의 `:root` 토큰으로 분리 → design봇이 브랜드 비주얼 정교화 가능.

## 실행
```
python3 -m http.server 8971 --bind 127.0.0.1
# http://127.0.0.1:8971/index.html
```

## 구조
- `index.html` / `styles.css`(디자인 토큰) / `app.js`(JSON fetch·필터·렌더)
- `data/menus.json` — 메뉴 29종 + 계산된 영양성분 + 계산근거(basis) + status
- `data/ingredients.json` — 재료별 표준 영양데이터(추정) + 계량 기준 + 확인필요 가정
- `build/compute.py` — 원본 메뉴 + 표준값 → menus.json 재생성(재검증용)
- `build/naver_menus_raw.json` — 네이버 플레이스 원본 스냅샷

## 메뉴 데이터 확보
✅ **성공.** 네이버 플레이스(그릴박스 노량진점, placeId `1093880694`)에서 메뉴 29종의
**이름·설명·가격·이미지 CDN URL** 전량 확보(예약 URL은 "포장주문" 플레이스홀더뿐이라 플레이스에서 취득).
이미지는 네이버 CDN(ldb-phinf.pstatic.net) 직접 참조.

## 영양성분 계산 기준

- 확정 계량(형 지시): **비프=소목살**, **밥=180g**, **파스타=150g**.

## ⚠️ 형에게 확인받아야 할 정보 (추정 정확도용)
1. **치킨/포크 부위** — 비프만 소목살로 확정됨. 치킨=닭다리살, 포크=돼지목심으로 **가정**해 계산. 실제 부위(예: 닭가슴살이면 칼로리↓·단백질↑) 확인 필요.
2. **스테이크 중량 기준** — 표기 200/300/500g이 조리 전(생) vs 조리 후(제공) 중량인지. 현재 "제공 중량"으로 간주.
3. **일본식 카레소스 1인분 중량**(약 150g으로 가정)·구성.
4. **강황 저당밥 / 저당 파스타**(비프포크 메뉴) — 실제 탄수화물이 표준 밥/파스타보다 낮을 수 있음. 현재 표준값 적용(보수적).
5. 음료 중 아메리카노 외 실제 영양성분표가 있으면 반영 가능.
